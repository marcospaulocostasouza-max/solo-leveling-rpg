# Design System Oficial do Projeto

Este documento define a identidade visual oficial do bot.

Todas as mensagens enviadas pelo bot devem seguir obrigatoriamente este padrão.

Nenhum comando poderá criar sua própria identidade visual.

A prioridade é manter consistência entre todos os sistemas do projeto.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Referências Oficiais

Os seguintes sistemas representam a identidade visual definitiva do projeto:

* !ficha
* !jogador
* Ficha de Técnicas

Sempre que um novo sistema for desenvolvido ou um sistema existente for alterado, utilize esses três comandos como referência principal.

O objetivo é que qualquer mensagem pareça fazer parte do mesmo projeto.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Objetivo

Todas as mensagens devem transmitir:

* Organização.
* Hierarquia visual.
* Elegância.
* Consistência.
* Facilidade de leitura.
* Aparência profissional.

Nunca produzir mensagens visualmente poluídas.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Hierarquia Visual

Toda mensagem deve possuir a seguinte ordem:

1. Título.
2. Conteúdo principal.
3. Informações secundárias.
4. Explicações.
5. Observações (quando necessário).

Nunca misturar essas categorias.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Títulos

Todo título deve utilizar:

* Fonte Unicode oficial do projeto.
* Negrito utilizando *texto*.

Nunca utilizar títulos simples quando houver um título equivalente já existente em outro sistema.

A identidade visual dos títulos deve permanecer exatamente igual em todos os comandos.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Subtítulos

Todo subtítulo também deve utilizar:

* Fonte Unicode oficial.
* Negrito.

Os subtítulos devem seguir exatamente a mesma identidade utilizada pelos comandos de referência.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Textos

Toda descrição deve utilizar:

*texto*

Isso inclui:

* descrições;
* histórias;
* narrativas;
* efeitos;
* observações;
* mensagens informativas;
* textos curtos;
* textos longos.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Explicações

Toda definição, explicação, aviso ou instrução deve utilizar:

> texto

Nunca misturar explicações com o restante do conteúdo.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Fontes Unicode

É obrigatório utilizar fontes Unicode.

Porém:

Nunca misturar estilos diferentes.

Cada categoria deve utilizar sempre a mesma fonte.

Exemplo:

* Títulos → Fonte A
* Subtítulos → Fonte A
* Corpo → Fonte padrão
* Valores → Fonte padrão

Caso exista uma fonte já utilizada em !ficha, !jogador ou na ficha de técnicas, ela passa a ser considerada a fonte oficial do projeto.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Alinhamento

Toda informação semelhante deve permanecer alinhada.

Nunca deixar colunas desalinhadas.

Sempre utilizar largura consistente.

Caso exista uma lista de atributos, valores, equipamentos, estatísticas ou qualquer informação semelhante, o alinhamento deve ser perfeito.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Espaçamento

Nunca deixar blocos excessivamente juntos.

Nunca deixar espaços exagerados.

Cada seção deve possuir espaçamento uniforme.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Separadores

Sempre utilizar o mesmo estilo de separadores.

Nunca misturar estilos diferentes na mesma mensagem.

Caso um sistema utilize um separador específico, os demais sistemas equivalentes devem utilizar o mesmo padrão.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Listas

Toda lista deve possuir organização visual.

Nunca deixar itens desalinhados.

Nunca misturar categorias diferentes.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Fichas

Toda ficha deve possuir:

Título.

Informações principais.

Informações secundárias.

Explicações.

Observações.

Sempre nessa ordem.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Menus

Todo menu deve seguir:

Título.

Categorias.

Comandos.

Observações.

Nunca alterar essa estrutura.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Inventários

Os inventários devem seguir exatamente a identidade visual da ficha do jogador.

Itens organizados.

Categorias organizadas.

Alinhamento perfeito.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Equipamentos

Os equipamentos devem utilizar exatamente o mesmo padrão do inventário.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Técnicas

As fichas de técnicas representam o padrão oficial.

Nunca criar um estilo diferente.

Toda técnica nova deve parecer fazer parte das técnicas já existentes.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Atributos

Os atributos devem permanecer alinhados.

Nunca alterar a ordem visual.

Nunca utilizar espaçamentos inconsistentes.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Mensagens de Erro

Devem ser objetivas.

Explicar claramente o problema.

Caso necessário utilizar:

> explicação

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Mensagens de Sucesso

Devem informar:

* O que aconteceu.
* Resultado.
* Próximo passo (quando existir).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Mensagens de Confirmação

Devem ser simples.

Objetivas.

Sem excesso de texto.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Consistência

Antes de finalizar qualquer mensagem, compare sua aparência com:

* !ficha
* !jogador
* Ficha de Técnicas

Caso exista diferença visual, adapte o layout até que ele pareça pertencer ao mesmo sistema.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

# Regra Principal

Nunca criar uma identidade visual nova para um comando.

Sempre reutilizar o padrão já existente no projeto.

Caso um comando esteja visualmente superior aos demais, ele deverá servir como referência para futuras atualizações.

A identidade visual do projeto deve evoluir de forma uniforme, mantendo sempre o mesmo estilo entre todos os sistemas do bot.

Este documento possui prioridade sobre qualquer decisão estética durante o desenvolvimento.
